LegacySignal for COBOL

The documentation and impact-analysis work that mainframe teams otherwise pay consultants for — or spend days doing by hand. LegacySignal inventories your entire COBOL estate, generates a documentation page for every program (files, copybooks, DB2 tables, CICS commands, called programs, paragraph map), maps who-calls-whom, and answers “what breaks if I change this?” before you change it. Designed with input from a working mainframe developer. Read-only by design: it analyses and reports; it never modifies a single line of your source.

What it does

Full estate inventory

Every program, copybook and job in a folder — type, size and a one-line summary, in one report.

Generated documentation

A documentation brief per program: files used, copybooks, DB2 tables, CICS commands, calls and paragraph map.

Impact analysis

Pick a program, copybook or field and see everything that touches it — before you change it.

Call maps & JCL chains

Who-calls-whom across the estate, plus job → step → program → dataset chains from your JCL.

DB2 & copybook matrices

Which tables each program reads or writes, and which copybooks are used where — including dead ones nobody references.

Modernisation briefs

A complexity score and migration brief per program: what it does, what it touches, and where the risk sits.

LegacySignal for COBOL — questions

Will it change my programs?

Never. Analysis and reports only. Documentation is generated into a separate output folder that you choose and approve — your source files are untouched.

How exact is the analysis?

It is careful text parsing with fixed-format awareness — a documentation and impact aid, not a compiler. Dynamic calls and generated code can hide relationships, and the connector says so in its own docs instead of pretending otherwise.

Does it cover DB2, CICS and JCL?

Yes — EXEC SQL tables and operations, EXEC CICS commands, and JCL job/step/dataset chains are all extracted into the reports.
