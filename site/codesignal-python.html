CodeSignal for Python

Not another “explain this file” — your Muse can already do that. CodeSignal is the standing health system for a Python project: a full repo map, generated documentation with docstring-coverage scores, a dependency inventory checked against your requirements, dead-code and complexity rankings, and a weekly sweep that tells you what drifted. Real analysis, built on Python's own AST — and read-only by design: it never modifies your source, and it never runs your tests unless you explicitly approve it.

What it does

Repo map

Every module, class and function in the tree, with sizes — the shape of your project on one page.

Generated documentation

Per-module docs from signatures and docstrings, with an honest docstring-coverage percentage.

Dependency inventory

The full import graph plus third-party dependencies, cross-checked against requirements.txt / pyproject.toml.

Dead code & complexity

Likely-unused functions and imports (labelled as heuristics), and your most complex functions ranked.

TODO sweep

Every TODO, FIXME and HACK in the project, with file and line — nothing quietly forgotten.

Syntax & test discovery

A compile check across the tree without executing anything, and a map of your tests — discovery only, never run by default.

Safety notes

  • Read-only by design. CodeSignal analyses and reports. It never modifies your source code — generated documentation is written only to a separate output folder you name and approve.
  • Your code stays yours. Everything runs inside your own Muse, on your own machine. Plugvana never receives, stores or sees your code.
  • Tests are never run by default. Running tests executes code, so test discovery is read-only; execution stays approval-gated and off unless you ask for it.

CodeSignal for Python — questions

How exact is the dead-code report?

Structure comes from Python's AST, which is exact. Dead code is a labelled heuristic — dynamic dispatch and reflection can hide real usage, and the report says so rather than pretending certainty.

Will it run my test suite?

Not by default, and never silently. It discovers and maps tests read-only; executing them is your explicit call, because tests run arbitrary code.

Where does my code go?

Nowhere. Analysis happens inside your own Muse, on your own machine.
