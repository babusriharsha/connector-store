StatSignal for SAS

The estate knowledge SAS teams in pharma, finance and insurance usually keep in someone's head. StatSignal inventories every program and macro, digests run logs into error and warning counts with context, maps dataset lineage — which programs create the data, which ones read it — and answers impact questions before a change ships. Read-only by design: it analyses and reports; it never modifies your source — a property that matters in validated and regulated environments.

What it does

Estate inventory

Every SAS program and macro — size, purpose from its header comments, librefs used — in one report.

Log scanner

ERROR and WARNING counts from a run log, each with context lines and a plain clean-run verdict.

Dataset lineage

DATA and PROC step lineage: which datasets each program reads and creates, LIBNAME-aware.

Macro documentation

Every macro with its parameters and defaults, and every place each one is called.

Impact analysis

Name a dataset or a macro and see every program that touches it — before you change it.

Estate health report

Inventory, lineage and risk flags in one pass — orphan programs, unlibref'd datasets, missing error checks.

StatSignal for SAS — questions

Will it change my programs?

Never. Analysis and reports only — your source files are untouched, which is exactly what a validated environment needs.

How exact is the lineage?

It is careful text parsing: LIBNAME-aware and name-based for macros. Code generated dynamically (for example via CALL EXECUTE) can hide lineage, and the connector says so plainly instead of pretending otherwise.

Where do my code and data go?

Nowhere. Analysis happens inside your own Muse, on your own machine.
